## TCC / permissions — THE REBUILD TAX (learned the hard way)

Every `npm run tauri build` re-signs the .app with a NEW ad-hoc signature.
TCC ties grants to the recorded signature, so after every rebuild the
permission checkboxes still LOOK on but the grants are dead. Symptom: hotkey
pill only appears while RootVox itself is focused (an unauthorized tap still
receives its own process's events — that asymmetry is the tell).

The hotkey tap is `ListenOnly` → governed by **Input Monitoring**
(ListenEvent), NOT Accessibility. Injection = Accessibility. Recording =
Microphone. All three break on rebuild; toggling checkboxes does NOT fix it.

**Post-rebuild ritual:**
```bash
tccutil reset ListenEvent com.educoben.rootvox
tccutil reset Accessibility com.educoben.rootvox
tccutil reset Microphone com.educoben.rootvox
```
then relaunch the app and re-grant the fresh prompts (restart app after).

**✅ PERMANENT FIX SHIPPED (end of session):** the app now signs with a
stable self-signed cert — "RootVox Dev" in the login keychain (created via
Keychain Access → Certificate Assistant, Code Signing type, trust set to
Always Trust), wired via `bundle.macOS.signingIdentity` in tauri.conf.json.
Grants now SURVIVE rebuilds. If the cert is ever deleted/expired (5yr
default), recreate it with the same name; expect exactly one permission
redo. `permissions.rs` also now requests Input Monitoring + Accessibility
properly at launch (no more silent tap failure or pane +-button hunting),
and lib.rs warms up the mic at startup — fires the mic prompt at launch AND
fixes the lost-first-utterance bug.

**Resolved endgame (all shipped + user-verified in the installed .app):**
- stt.rs strips whisper's bracketed non-speech markers ("[BLANK_AUDIO]",
  "(coughing)") so silent recordings inject nothing.
- **Root cause of "mic never prompts / always silence" in the .app:** Tauri's
  default Info.plist lacks `NSMicrophoneUsageDescription` — macOS silently
  denies mic (no prompt, zeros audio) to apps without it. Fixed with
  `src-tauri/Info.plist` (Tauri auto-merges it into the bundle). Dev builds
  masked this via the terminal's own grant. Verify after any bundle change:
  `plutil -p /Applications/RootVox.app/Contents/Info.plist | grep -i microphone`
- Accessibility + Input Monitoring panes need MANUAL add (+ button) after a
  `tccutil reset` — macOS won't re-prompt for those (only mic auto-prompts,
  and only with the plist key present).

## Debugging crumbs (save future-you hours)

- Release build fails in ggml with `'path' is unavailable` →
  deployment-target problem; see CLAUDE.md "Release packaging learnings".
- White window in release = webview rendered nothing; check the two
  macOSPrivateApi requirements, then right-click → Inspect Element
  (devtools feature).
- Dictation pipeline logs everything to stderr with `[stt]`, `[cleanup]`,
  `[pipeline]`, `[overlay]`, `[config]` prefixes — `tauri dev` shows them
  directly; for the .app use Console.app filtered on "rootvox".
- Dev and release instances both grab the hotkey — never run both at once
  (double injection).
